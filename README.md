# Information Security & AI Governance Lab

This is a practical cybersecurity portfolio project I created to demonstrate how I approach information security, risk assessment, data protection, AI security, incident response, and security controls.

I created a fictional organization called Mwangaza Research to use as the case study.

Mwangaza Research collects research participant information, uses cloud services, has remote employees, works with third-party vendors, and uses AI tools as part of its work.

## The Scenario

I created a security scenario where a researcher accidentally uploads research participant information to an unapproved public AI tool.

This creates several security and data protection risks, including:

* Exposure of personal information
* Loss of confidentiality
* Third-party processing of sensitive information
* Unclear data retention
* Possible contractual or regulatory consequences
* Loss of trust

I used this scenario to work through the security problem from identification to risk treatment.

## How I Approached the Problem

I followed this process:

**Assets → Risks → AI Assessment → Policy → Incident Response → Security Controls**

### 1. Asset Inventory

I first identified the important systems, information, and resources that the organization needs to protect.

[View the Asset Inventory](asset-inventory.md)

### 2. Risk Register

I then identified the main security risks and assessed their likelihood, impact, severity, and treatment.

[View the Risk Register](risk-register.md)

### 3. AI Tool Assessment

I assessed different types of AI tools based on how they would be used and the sensitivity of the information being processed.

One of the main lessons from this assessment was that the risk is not only about whether an AI tool is secure. It also depends on what information an employee puts into the tool.

[View the AI Tool Assessment](ai-tool-assessment.md)

### 4. AI Acceptable Use Policy

I created a simple AI acceptable use policy to define what employees can and cannot submit to AI tools.

The policy covers sensitive information such as:

* Research participant information
* Employee personal information
* Passwords and credentials
* API keys and access tokens
* Confidential business information
* Financial information
* Sensitive research information
* Private client or partner information

[View the AI Acceptable Use Policy](ai-acceptable-use-policy.md)

### 5. Incident Response

I then created an incident response process for what should happen if sensitive information is accidentally exposed.

The process covers:

**Detect → Assess → Contain → Investigate → Remediate → Recover → Learn**

[View the Incident Response Plan](incident-response.md)

### 6. Security Controls

Finally, I mapped the risks I identified to practical security controls.

These include:

* Multi-factor authentication
* Access reviews
* Data classification
* Encryption
* Security awareness
* AI acceptable use
* Approved AI tools
* Vendor security assessments
* Security monitoring
* Incident response
* Repository access controls

[View the Security Controls](security-controls.md)

## What I Learned

One of the main things I wanted to demonstrate with this project is that information security and AI governance cannot be treated as completely separate problems.

For example, an organization may have a secure AI tool, but that does not automatically mean every type of information should be entered into it.

The organization also needs to understand:

* What information it has
* How sensitive that information is
* Who can access it
* Which tools can process it
* What could happen if the information is exposed
* What controls are needed
* What happens when something goes wrong

This is the approach I followed throughout this project.
